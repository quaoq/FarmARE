# FarmARE L3 大豆正式场景系统

## 1. 总览

FarmARE 当前正式评估池包含 90 个 L3 full-season 大豆场景。场景覆盖 6 个真实大豆种子类型：HEIHE43、HEIHE50、HEINONG58、HEINONG60、HEINONG84、HEIKE71。L3 full-season 场景从播前或播种窗口开始，贯穿出苗、营养/水分/病虫草管理、R5/R6、成熟、收获、烘干和储藏，要求 oracle 或 agent 通过工具返回形成完整农事闭环。最终正式池用于评估 agent 是否能在真实品种、天气、土壤、病虫草、资源容量和收获后质量约束下，做出观察驱动、分区化、证据支持的专家管理。

## 2. 场景脚本结构

L3 full-season 场景主要位于 `are/simulation/scenarios/scenario_farm_world_fullseason_v2/`。单个 wrapper 文件通常继承 `Scenario`，在 `init_and_populate_apps()` 中读取 catalog `SPEC`，调用 `init_batch_apps()` 安装 FarmWorld、Weather、Sensor、Drone、Robot、Tractor、FieldOps 等 app，并调用 `build_batch_events()` 构建 oracle 事件图。`harbin_l3_batch_catalog.py` 保存 catalog-driven/class-config 场景的 `ScenarioSpec`：包括 `scenario_id`、`profile_name`、`briefing_text`、seed stocks、planting zones、soil hydraulic modifiers、prior histories、management regime、postharvest market、action windows 和 harvest zones。`profiles.py` 提供物理 profile 与真实种子参数，profile 名称连接场景隐藏农艺条件和 physics engine。

代码里同时存在几类结构：standalone ARE-style scenario script 直接写 scenario 类和事件；catalog-driven/class-config scenario 用 wrapper 文件加 catalog `ScenarioSpec` 复用批量流程；trace runner 位于 `scripts/fullseason/`，只在导出证据时插入 trace app，不进入 production scenario；oracle flow construction 由 `build_batch_events()`、`_prep_field()`、`_plant_zone()`、`_wait_check_window()`、`_diagnose_target()`、`_run_window_actions()` 和 `harvest_range()` 等函数组合完成；evidence/export artifacts 则由 trace utilities 从真实 event log、daily state 和 final summary 中导出。

初始化时，`__init__`/config 设置 scenario id、起始时间、app、库存、管理 regime 和 postharvest market。profile setup 设置隐藏的天气、土壤、病虫草、残茬、排水、资源容量和种子响应。seed plan 和 ridge zones 通过 `PlantingZone`、`zones`、`harvest_zones` 和 soil/history modifiers 赋给 ridge 范围。oracle 先发送 agent-facing briefing，再按天气/土壤/库存/机器状态准备田块，播种后通过 sensor、drone、robot 和 range state 观察，将证据映射到 planting、emergence/stand check、fertigation、irrigation、weed control、fungicide、pesticide、harvest、drying、storage 以及 capacity/budget handling。

## 3. 证据导出流程

`scripts/fullseason/` 下的 trace runner 通过 `make_trace_scenario()` 给 production scenario 动态插入 `HarbinL3DailyTraceApp`。该 trace app 的 `capture_daily_state()` 在关键日读取 FarmWorld physics state、weather snapshot、management regime、postharvest market、zone summaries、ridge details 和 recent action log，然后写入 field summary CSV、ridge-state CSV 和 oracle trace JSON。

最终 acceptance artifacts 将底层证据整理为 `raw_event_log`、`daily_state`、`checkpoint_summary`、`final_summary`、`compact_action_workflows`、`representative_ridge_yield`、final one-row scenario inventory 和 final acceptance table。`raw_event_log` 保留真实事件顺序；`daily_state` 展示每个 ridge/zone 的 stage、GDD、NDVI、LAI、biomass、soil moisture、water/nutrient/biotic pressures、grain moisture 和 yield proxy；`checkpoint_summary` 抽取播种、出苗、压力出现、干预、R5/R6、R8、收获和储藏等关键节点；`compact_action_workflows` 把多次 tool call 压缩成人类可读的关键农事步骤；`representative_ridge_yield` 用 affected/reference/seed/density/harvest batch 展示代表区域状态；final one-row inventory 和 acceptance table 用于人工复核 90 个正式场景是否具备 agent task、seed plan、oracle workflow、primary metric 和最终产量证据。

## 4. 十类场景类型

- Type 0: Basic ICMLW / baseline scenarios：基础 full-season 大豆管理、标准任务、标准 oracle flow，承接已有 ICMLW 场景脉络。
- Type 1: Soybean seed variants：真实大豆品种 HEIHE43、HEIHE50、HEINONG58、HEINONG60、HEINONG84、HEIKE71；差异包括成熟期、出苗、密度最适、抗逆性、抗病虫草和产量潜力。
- Type 2: Staggered plot cycles：不同 ridge block 不同播期或生育阶段，导致出苗、GDD、phenology、grain moisture 和 harvest window 不同。
- Type 3: Season weather types：干旱季、湿六月、冷春、热干夏、凉8月、晚雨季；天气改变正确 oracle 时机。
- Type 4: Soil water-holding and drainage variants：fast-draining、poor drainage、compaction、低持水、高残茬/trafficability、local soil constraint。
- Type 5: Biotic-pressure regimes：病害、虫害和草害压力，也包括 disease/weed/insect 造成 low NDVI 或绿色度混淆的诊断场景。
- Type 6: Management objective variants：最大产量、节水、低化学投入、少机械进地、保护收获质量等目标改变决策。
- Type 7: Operational capacity and timing constraints：喷药预算、灌溉水量、肥料配额、收获机天数、烘干能力、储藏容量、机械可用性和燃油限制。
- Type 8: Rotation and prior-field-history regimes：前茬大豆、高残茬、压实、weed seedbank、prior disease history、nutrient carryover。
- Type 9: Market and post-harvest quality regimes：籽粒水分、烘干成本、储藏安全、market discount、quality batch、高水分交售和收获时机。
- Type 10: Sustainability and organic-management regimes：有机、低化学、低投入、节水、低碳和 allowed inputs。

## 6. 产量与主指标影响说明

错误 agent 行为不一定只表现为最终产量大幅下降。水分/干旱、病害、虫害、杂草、营养/肥力、建苗/stand 和 cultivar/stage 管理通常应在 final yield、代表区域 biomass、NDVI、LAI 或 stress state 中体现差异。收获后、传感器、市场/质量、低碳/燃油和资源预算场景的主要信号可能是 primary metric，例如 dryer capacity、storage status、sensor_status、alternative_observation_used、discount_loss、operation_count、fuel_proxy、water_budget_remaining 或 spray_budget_remaining，而不是单纯的生物产量。

| scenario group | wrong policy example | expected signal | evidence field |
|---|---|---|---|
| 水分/干旱 | 全田灌溉或忽略真正 dry patch | 目标区 water_stress 低、预算消耗不合理、产量/biomass 下降 | soil_moisture, water_stress, irrigated_ridges, water_budget_remaining, final_yield_kg |
| 病害 | 未确认就全田杀菌，或阈值后不处理 | disease_pressure 持续升高或 wrong target | disease_pressure, fungicide_target, post_treatment_trend, final_yield_kg |
| 虫害 | 阈值不足时喷药或高虫压不喷 | insect_pressure 和 spray budget 表现异常 | insect_pressure, pesticide_target, spray_budget_remaining, yield proxy |
| 杂草 | 把 field NDVI 偏高误判为作物健康 | weed_pressure/weed_cover 高、crop state 恢复差 | weed_pressure, weed_cover, field_ndvi, crop_ndvi, LAI, biomass |
| 营养/肥力 | 把病害或水分问题当作缺肥，或不补真正 nutrient zone | nutrient_stress 和 biomass 恢复不足 | nutrient_stress, fertigation_target, biomass, NDVI, final_yield_kg |
| 建苗/stand | 漏播/出苗弱未补种，或全田重播 | stand_fraction、LAI 和成熟窗口受影响 | stand_fraction, emergence check, replant_target, stage, final_yield_kg |
| 品种/stage 管理 | 把不同品种/播期当作同一 stage | 分区 harvest/maturity/water/disease 决策错误 | growth_stage_by_zone, GDD, grain_moisture, treatment_target_by_zone |
| 收获后 | 高水分直接入库或不按容量分批 | 储藏/烘干状态不安全 | grain_moisture, drying_status, storage_status, storage_grain_moisture |
| 传感器/质量/市场 | 传感器失败后不替代观测，或忽略折扣 | primary metric 异常但 yield 不一定大降 | sensor_status, alternative_observation_used, moisture_discount, discount_loss, net_return_proxy |
| 低碳/燃油/资源预算 | 早期浪费有限资源，后续关键窗口无资源 | resource remaining 和 operation proxy 变差 | operation_count, fuel_proxy, machine_available_days, budget_remaining |

## 7. 最终说明
